# Registro de peso: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tabela `pesos`, em que cada dia usa o peso da sua data, com um cartão "Peso" no Perfil e a tabela incluída na exportação.

**Architecture:**
- A tabela vem do `SCHEMA` (`CREATE IF NOT EXISTS`), e `migrar` semeia a partir do perfil na v4.
- Uma função pura `pesoNaData` resolve o peso de cada dia.
- As contas recebem um perfil "do dia" (`{ ...perfil, pesoKg }`), sem mudar as fórmulas de `energia.ts`.

**Tech Stack:** React 19, TS, sql.js, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-14-peso-design.md`

## Global Constraints
- **Faixa de peso:** de 30 a 300 kg, a mesma validação de hoje.
- **Um peso por dia:** registrar de novo no mesmo dia substitui o anterior.
- **Peso de um dia:** o último registro com `data ≤ dia`. Antes do primeiro registro, vale o primeiro.
- **`perfil.peso_kg`:** sempre igual ao registro mais recente.
- **Último registro:** não pode ser apagado.
- **Backups v1 a v3:** continuam válidos. `TABELAS_OBRIGATORIAS` não muda.
- **Publicação:** só com o ok do Arthur.

## Review Focus
1. **Peso registrado com vírgula** ("82,5"): é aceito. Teste na Task 3.
2. **Registrar entre 00:00 e 04:59:** vai para o dia anterior do app (`hojeApp`). Teste na Task 3.
3. **Importar backup v3 (sem `pesos`):** a migração semeia a tabela a partir do perfil. Teste na Task 1.
4. **Apagar o registro mais recente:** `perfil.peso_kg` volta para o anterior. Teste na Task 1.
5. **Usuário novo:** o primeiro cadastro cria o primeiro peso. Teste na Task 3.
