# Apelidos de busca: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Busca por apelidos: uma lista pronta (~50 alimentos) e apelidos ensinados pelo Arthur, consultados junto com o nome e priorizados na ordem dos resultados.

**Architecture:** A tabela nova `apelidos` é criada pelo `SCHEMA` e marcada na migração v3. A lista do app vive em `src/db/apelidos.ts` e é sincronizada a cada abertura (só os de `origem='lista'`). `buscarAlimentos` procura no nome **ou** nos apelidos. A UI ganha o "Ensinar" na tela Adicionar e a lista no Perfil.

**Tech Stack:** React 19, TS, sql.js, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-14-apelidos-design.md`

## Global Constraints

- **Origem dos apelidos:** `origem IN ('lista','usuario')`. A sincronização da lista **nunca** toca nos de `usuario`.
- **Backups antigos:** v1 e v2 continuam válidos. `validarBancoImportado` exige só `perfil`, `alimentos`, `refeicoes` e `treinos`.
- **Ordem da busca:**
  1. Alimentos encontrados por apelido do usuário.
  2. Alimentos encontrados por apelido da lista.
  3. Alimentos cadastrados pelo Arthur.
  4. Nomes mais curtos.
- **Registro sem passos a mais:** ensinar um apelido não acrescenta nenhum toque ao fluxo normal.
- **Publicação:** não publicar sem o ok do Arthur.

## Review Focus

1. **Apelido duplicado:** ensinar duas vezes o mesmo termo para o mesmo alimento não cria uma linha repetida. Teste na Task 1.
2. **Apagar um alimento cadastrado:** não existe no app, mas `apelidos.alimento_id` é FK. Nada a testar além do schema.
3. **Termo com acento ou maiúsculas:** "Pão Francês" encontra o mesmo que "pao frances". Teste na Task 3.
4. **Lista com nome que não existe na TACO:** não quebra a abertura (o item é ignorado), e um teste garante que hoje todos existem. Teste na Task 2.
5. **Busca por termo vazio ou com espaços:** continua devolvendo `[]`. Coberto pelos testes atuais.

### Task 1: Tabela `apelidos`, migração v3 e funções do banco

**Files:** `src/db/schema.sql.ts`, `src/db/migracao.ts`, `src/db/repos.ts`, `src/exportar.ts`, `src/db/migracao.test.ts`, `src/db/repos.test.ts`, `src/exportar.test.ts`

**Interfaces (Produces):**
- **Tabela:** `CREATE TABLE IF NOT EXISTS apelidos (id INTEGER PRIMARY KEY AUTOINCREMENT, alimento_id INTEGER NOT NULL REFERENCES alimentos(id), termo TEXT NOT NULL, termo_busca TEXT NOT NULL, origem TEXT NOT NULL CHECK (origem IN ('lista','usuario')), UNIQUE (alimento_id, termo_busca, origem))`, com índice em `termo_busca`.
- **Migração:** `VERSAO_BANCO = 3`.
- **Tipos:** `interface Apelido { id: number; alimentoId: number; termo: string; nomeAlimento: string }`.
- **Funções em `repos.ts`:**
  - `adicionarApelido(b: Banco, alimentoId: number, termo: string): Promise<void>`: grava com origem `usuario` e ignora duplicados (`INSERT OR IGNORE`).
  - `apelidosDoUsuario(b: Banco): Apelido[]`, ordenada por termo.
  - `removerApelido(b: Banco, id: number): Promise<void>`
- **Exportação em `exportar.ts`:**
  - `TABELAS` ganha `'apelidos'` (CSV).
  - Novo `TABELAS_OBRIGATORIAS = ['perfil','alimentos','refeicoes','treinos']`, usado por `validarBancoImportado`.

- [ ] **Escrever os testes que falham.**
  - **Migração:**
    - Um banco v2 (`user_version = 2`, sem `apelidos`) abre com versão 3 e aceita `adicionarApelido`.
    - O teste v1 existente passa a esperar versão 3.
  - **repos:**
    - `adicionarApelido` duas vezes para o mesmo alimento com "Marmita da Vó" e "marmita da vo" resulta em uma linha.
    - `apelidosDoUsuario` devolve `nomeAlimento`.
    - `removerApelido` apaga.
  - **exportar:**
    - Um banco sem a tabela `apelidos` passa em `validarBancoImportado`.
    - `tabelaParaCsv(b, 'apelidos')` tem o cabeçalho `id;alimento_id;termo;termo_busca;origem`.
- [ ] **Rodar** `npx vitest run src/db src/exportar.test.ts`. Esperado: FAIL.
- [ ] **Implementar.** `termo_busca = normalizar(termo.trim())` com espaços repetidos colapsados. Um banco v2 recebe a tabela pelo `SCHEMA`, e `migrar` só ajusta a versão.
- [ ] **Rodar** `npx vitest run`. Esperado: PASS.
- [ ] **Commit** `feat: tabela de apelidos e migração v3`.

### Task 2: Lista pronta e sincronização

**Files:** criar `src/db/apelidos.ts` e `src/db/apelidos.test.ts`; alterar `src/App.tsx` (`iniciarBanco` chama a sincronização depois de `semearTaco`)

**Interfaces:**
- **Consumes:** tabela `apelidos` (Task 1), `normalizar`.
- **Produces:**
  - `APELIDOS_LISTA: Record<string, string[]>`, com o nome exato da TACO como chave e os termos como valor.
  - `sincronizarApelidosLista(b: Banco): void`: numa transação, apaga os de origem `lista` e insere a lista atual, ignorando nomes que não existem com `origem='TACO'`. Não chama `salvar`.

- [ ] **Escrever os testes que falham.**
  - **Todo nome da lista existe na TACO:** toda chave de `APELIDOS_LISTA` existe em `public/taco.json` (ler com `readFileSync`).
  - **A sincronização não toca nos apelidos do usuário:**
    - Prepare: semear 2 alimentos TACO, com uma chave inexistente na lista via `vi.spyOn` (ou um parâmetro opcional `lista = APELIDOS_LISTA`, se for mais simples).
    - Ação: sincronizar duas vezes.
    - Esperado: a contagem de origem `lista` fica estável, um apelido `usuario` criado antes continua lá, e a chave inexistente não lança erro.
  - **Cobertura mínima da lista:** inclui "arroz branco" → `Arroz, tipo 1, cozido`, "carne moída" → `Carne, bovina, acém, moído, cozido`, "pãozinho" → `Pão, trigo, francês` e "peito de frango" → `Frango, peito, sem pele, grelhado`.
- [ ] **Rodar.** Esperado: FAIL.
- [ ] **Implementar.**
  - A assinatura fica `sincronizarApelidosLista(b: Banco, lista = APELIDOS_LISTA)`.
  - A lista tem cerca de 50 alimentos do dia a dia: arroz, feijão (carioca e preto), carnes comuns, frango, ovo, pães, leite, café, frutas comuns, batata, mandioca, macarrão, queijos, presunto, refrigerante, cerveja, chocolate, açúcar, azeite e manteiga.
  - Usar só nomes confirmados em `public/taco.json`.
- [ ] **Rodar** `npx vitest run`. Esperado: PASS.
- [ ] **Commit** `feat: lista pronta de apelidos sincronizada ao abrir`.

### Task 3: Busca por apelido

**Files:** `src/db/repos.ts` (`buscarAlimentos`), `src/db/repos.test.ts`

- [ ] **Escrever os testes que falham.**
  - **Prepare:** alimentos `Arroz, integral, cozido` e `Arroz, tipo 1, cozido` (TACO), apelido de lista "arroz branco" e "arroz" → tipo 1.
  - **Casos:**
    - `buscarAlimentos(b, 'arroz branco')[0].nome` é `'Arroz, tipo 1, cozido'`.
    - `buscarAlimentos(b, 'arroz')[0].nome` é `'Arroz, tipo 1, cozido'`.
    - `buscarAlimentos(b, 'Arroz Branco')` dá o mesmo resultado (Review Focus 3).
    - Um apelido do usuário "marmita" → integral faz `buscarAlimentos(b, 'marmita')` devolver só o integral.
    - Com o mesmo termo "arroz" como apelido de usuário para o integral, o integral vem antes do tipo 1 (o usuário vence a lista).
    - Um alimento encontrado por dois apelidos aparece uma vez só.
- [ ] **Rodar.** Esperado: FAIL.
- [ ] **Implementar.**
  - Envolver a consulta num subselect com a coluna `via`:
    - `via` = `MIN(CASE origem WHEN 'usuario' THEN 0 ELSE 1 END)` dos apelidos daquele alimento cujo `termo_busca` contém todas as palavras.
    - `via` = `NULL` quando nenhum apelido bate.
  - Filtro: o nome contém todas as palavras **ou** `via IS NOT NULL`.
  - Ordem: `ORDER BY via IS NULL, via, origem = 'TACO', length(nome)`.
- [ ] **Rodar** `npx vitest run`. Esperado: PASS.
- [ ] **Commit** `feat: busca encontra alimentos por apelido`.

    - Com um apelido do usuário, o cartão "Seus apelidos" mostra `marmita → Arroz`.
