# Porções Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Registrar refeições por porção caseira (1 xícara, 2 fatias, 1 ovo) com lista pronta + porções do usuário, botões − e + e lembrança da última porção.

**Architecture:** Nova tabela `porcoes` e duas colunas opcionais em `refeicoes` (`qtd`, `porcao`), banco v5. `gramas`/`kcal` seguem como fonte das contas: a porção só converte quantidade → gramas na hora de registrar. A lista pronta vive em `src/db/porcoes.ts` e é sincronizada a cada abertura do app, como `apelidos.ts`.

**Tech Stack:** React 19, TypeScript, sql.js, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-14-porcoes-design.md`

## Global Constraints
- `VERSAO_BANCO = 5`. Backups v1–v4 continuam importáveis (`TABELAS_OBRIGATORIAS` não muda).
- Bebidas: 1 ml = 1 g; o volume vai no nome da porção ("Xícara (180 ml)").
- − e + andam de 1 em 1; − não desce abaixo de 1; frações só digitando ("1,5", "0,5"). Sem − e + no modo Gramas.
- Porções da lista nunca aparecem em "Suas porções" e nunca são apagadas pelo usuário.
- Nada em vermelho; sem cobrança (mantém os tokens de `index.css`).
- Mensagens de commit terminam com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus
- Banco já migrado v1→v2 (refeicoes reconstruída sem `qtd`/`porcao`) chegando ao v5: as colunas precisam existir. → teste na Task 1.
- Usuário apaga a porção que foi a última usada: o alimento deve abrir no padrão, não quebrar. → teste na Task 3.
- Porção do usuário com o mesmo nome de uma da lista ("Xícara"): ambas aparecem; a lembrança escolhe a do usuário. → teste na Task 3.
- Quantidade digitada "1,5" depois de tocar + (estado texto vs número) mantém a conta certa. → teste na Task 3.
- Alimento custom sem porções abre em Gramas/100 e permite criar "Minha porção". → teste na Task 3.

### Task 3: Tela Adicionar com porções, − e + e lembrança

**Files:**
- Modify: `src/telas/Adicionar.tsx`, `src/index.css`
- Test: `src/telas/Adicionar.test.tsx` (novo; montar como `Hoje.test.tsx` monta o provider de banco)

**Interfaces:**
- Consumes: `porcoesDoAlimento`, `adicionarPorcao`, `ultimoUso`, `addRefeicao` com `qtd/porcao` (Task 1); `parseGramas` (aceita "1,5", rejeita 0/vazio/texto) para a quantidade também.
- Produces: estado de seleção `{ tipo: 'gramas' } | { tipo: 'porcao'; porcao: Porcao }`.

Comportamento:
- Escolher alimento → seleção inicial por `ultimoUso`: se `porcao` bate com o nome de uma porção atual (preferir origem usuario em empate) → essa porção com `qtd`; se o último foi em gramas → Gramas com aqueles gramas; se não há histórico ou a porção sumiu → primeira de `porcoesDoAlimento`, qtd 1; sem porções → Gramas, 100.
- Fileira de botões (`role="radiogroup"`, cada um `role="radio"` com `aria-checked`): "Gramas", cada porção pelo nome, "+ Minha porção".
- Modo porção: label "Quantidade", botões `aria-label="Menos"`/`"Mais"` (+ → `Math.floor(q) + 1`; − → `Math.max(1, Math.ceil(q) - 1)`; com texto inválido, + vira 1). Texto mostrado: `"{gramas totais} g · {kcal} kcal"`.
- Adicionar em modo porção → `addRefeicao({ gramas: qtd * porcao.gramas, qtd, porcao: porcao.nome })`; modo gramas → sem qtd/porcao.
- "+ Minha porção" → mini-formulário (Nome, "Gramas ou ml", Salvar/Cancelar); salvar chama `adicionarPorcao`, recarrega as porções e seleciona a nova com qtd 1.
